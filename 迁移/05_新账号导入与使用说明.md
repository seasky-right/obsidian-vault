# 新账号导入与使用说明

> 版本日期：2026-08-03  
> 用途：指导新账号读取迁移材料、建立必要记忆，并避免把全部档案机械地保存为长期记忆。

## 1. 准备文件

账号级迁移材料包括：

1. `01_个人长期档案.md`
2. `02_交流与回答偏好.md`
3. `03_当前项目与未完事项.md`
4. `04_近期任务清单.md`
5. `05_新账号导入与使用说明.md`

此外，仍在本地运行的重要项目应另行保留：

- 项目代码；
- 本地文件；
- 本地聊天记录；
- 实验结果；
- 运行环境；
- 项目自己的交接文档。

账号级迁移材料只负责帮助新账号理解用户及其当前任务，不能替代具体项目的本地交接。

## 2. 不要直接依赖压缩包导入

可以把所有迁移材料放进一个 ZIP 压缩包，用于本地备份和传输，但不要把“上传 ZIP”作为主要导入方式。

更稳妥的操作是：

1. 在本地解压迁移包；
2. 将其中的 Markdown 文件分别上传；
3. 如果 Markdown 文件无法上传，可改成 TXT，或者直接粘贴文本；
4. 项目代码和大体量历史聊天不要与个人档案一次性混在一起上传。

完整账号导出的 ZIP 也应先解压，再找到 `conversations.json` 或带编号的对话 JSON 文件。它们只作为旧聊天档案使用。

## 3. 新账号中的准备

进入新账号后，打开：

`设置 → 个性化`

检查并开启：

- 引用已保存的记忆；
- 引用聊天记录。

长期稳定且希望在不同对话中持续使用的信息，应通过“已保存的记忆”保留。

聊天记录引用可以逐渐帮助新账号了解用户，但它不会精确保留过去聊天中的每一个细节。因此，重要背景不能只依赖聊天历史自动形成。

## 4. 建立迁移总控对话

在新账号中新建一个普通对话，命名为：

`账号迁移与个人总控`

不建议第一次导入就使用“项目专属记忆”的项目，因为项目专属记忆会隔离项目外的记忆和对话。个人长期背景需要在多个不同话题中发挥作用。

在该对话中依次上传：

1. `01_个人长期档案.md`
2. `02_交流与回答偏好.md`
3. `03_当前项目与未完事项.md`
4. `04_近期任务清单.md`
5. 本说明文件

可以一次上传多份，也可以分两次上传。若一次上传后模型混淆信息，应改为逐份读取。

## 5. 第一次导入时发送的消息

上传文件后，发送：

> 请完整阅读这些迁移文件。它们用于帮助你接续我在旧账号上的使用体验，但不是要求你把全部内容机械地保存为长期记忆。
>
> 请先区分：
>
> 1. 适合长期记住的稳定背景、目标和交互偏好；
> 2. 只适合作为当前任务上下文的内容；
> 3. 已结束的历史经历；
> 4. 近期任务和可能很快过时的信息；
> 5. 近期讨论兴趣，不能据此推断为永久爱好。
>
> 先不要复述全部文件。请输出一份精简的“建议长期记忆清单”和一份“当前任务摘要”，并指出文件之间是否存在矛盾、重复或可能过拟合的内容。以我之后提供的最新信息为准。

## 6. 审核长期记忆

新账号给出“建议长期记忆清单”后，不要直接确认全部内容。

逐项检查：

- 是否确实长期有效；
- 是否会影响未来回答；
- 是否把短期任务误写成长期身份；
- 是否把近期兴趣误写成永久爱好；
- 是否包含已经结束的项目；
- 是否出现没有明确提供的姓名、身份或推断；
- 是否写得过于具体，导致以后难以更新。

适合长期记住的内容通常包括：

- 教育和专业背景；
- 升学与长期发展方向；
- 稳定的技术方向偏好；
- 对 AI 辅助开发的基本态度；
- 少量重要的交流原则；
- 长期健康与训练目标；
- 常用设备；
- 当前核心工作方向。

不适合长期记住的内容通常包括：

- 每天具体吃了什么；
- 某晚几点睡；
- 某次训练动作；
- 最近一周的情绪；
- 临时软件故障；
- 已结束实习的细节；
- 尚未启动的项目构想；
- 近期讨论的明星、历史人物或商业事件；
- RPC 项目的全部代码和实验细节。

确认后，可以发送：

> 请只记住以下长期稳定信息：  
> （粘贴审核后的清单）  
> 其他内容只作为这次对话或相关项目的上下文，不要视为永久信息。

随后进入：

`设置 → 个性化 → 管理记忆`

检查实际保存的内容，并删除错误、重复或过度具体的记忆。

## 7. 当前任务如何处理

`03_当前项目与未完事项.md` 和 `04_近期任务清单.md` 具有时效性，不应永久不变。

当前应理解为：

- 智能体辅助 RPC 校正项目是唯一工作主线；
- 账号迁移是短期事务；
- CSP、六级、CSAPP 和健康管理为低频维持；
- 软件杯和升学判断等待节点；
- 其余项目可搁置。

这些状态以后发生变化时，应直接更新对应文件，或者在新对话中明确说明最新状态。

不要依靠旧文件长期维持已经过时的任务优先级。

## 8. 本地项目如何处理

很多项目的真实上下文保存在本地，包括：

- 代码；
- 项目文件；
- 本地聊天；
- 实验；
- 配置；
- 运行命令；
- 已否定方案；
- 技术决策。

这些内容不会因为导入个人迁移档案而自动转移。

当需要继续某个本地项目时，应单独建立项目交接材料。新账号接手时，优先读取项目目录中的真实文件和交接文档，不要仅凭账号记忆猜测项目状态。

RPC 项目尤其需要单独交接。当前个人档案只能说明它是主线，不能代替其具体技术上下文。

## 9. 旧聊天导出如何使用

拿到旧账号导出的数据后：

1. 解压导出 ZIP；
2. 找到 `conversations.json` 或带编号的对话 JSON 文件；
3. 将原始导出保存在本地，至少保留一份只读备份；
4. 不要把全部旧聊天当作长期记忆；
5. 可以在新账号新建一个“旧聊天档案查询”对话，上传 JSON 文件；
6. 文件过大时，拆分后上传，或者只筛选真正需要的聊天。

上传旧聊天文件的作用是以后查询历史内容。它不会：

- 恢复原来的侧边栏；
- 重新生成每一个旧对话；
- 自动迁移已保存记忆；
- 自动重建旧账号的完整聊天体验；
- 代替当前已经整理好的个人档案。

## 10. 迁移结果验收

导入后，在新账号中分别询问：

1. 你目前如何理解我的教育背景和长期方向？
2. 我当前唯一的工作主线是什么？
3. 哪些事情只是低频维持或暂时搁置？
4. 回答技术问题时，你应如何组织解释？
5. 哪些近期话题不应被当作永久兴趣？
6. 本地项目为什么还需要单独交接？
7. 哪些信息被保存为了长期记忆？

检查以下问题：

- 是否出现不属于用户的信息；
- 是否把近期兴趣当成永久标签；
- 是否把所有项目都说成正在同时推进；
- 是否忽略 RPC 的主线地位；
- 是否把大量临时健康状态保存为长期记忆；
- 是否形成过于僵硬的固定文风；
- 是否错误认为上传档案等于恢复全部旧聊天。

发现错误时，应立即纠正，并要求更新或删除相应记忆。

## 11. 何时可以清理旧账号

同时满足以下条件后，再清理旧账号：

- 所有迁移文件已保存到本地；
- 新账号已成功读取迁移材料；
- 长期记忆已检查；
- 主要本地项目已备份；
- RPC 等重要项目已有或计划制作独立交接；
- 旧账号导出文件已收到，或者已确认不再等待；
- 随机抽查新账号，能够正确说明背景和任务优先级；
- 账号原所有者确认可以删除相关内容。

删除旧账号聊天后，还应检查：

- 已保存记忆；
- 自定义指令；
- 上传文件；
- 项目；
- 自定义 GPT；
- 已连接的外部账号；
- 各设备上的登录状态。

## 12. 后续维护

迁移完成后，不需要频繁维护全部文件。

建议：

- 个人长期档案：发生重要长期变化时更新；
- 交流与回答偏好：只有出现明显问题时修改；
- 当前项目与任务清单：主线或优先级变化时更新；
- 本地项目交接：项目进入新阶段时更新；
- 旧聊天导出：只作为档案保留。

迁移文件的作用是帮助新账号顺利起步。随着新账号积累真实聊天记录，应逐渐依靠新的对话上下文和经过审核的记忆，而不是永久依赖迁移文件。
